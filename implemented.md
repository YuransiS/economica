# Глубокий технический разбор: Архитектура CRM Economica

Данный документ предназначен для разработчиков и описывает внутреннее устройство системы, алгоритмы обработки данных и механизмы интеграции.

---

## 1. Система авторизации и защиты (Security Layer)

Система защищена на уровне сервера Next.js с использованием Middleware, что исключает доступ к данным даже при попытке прямого вызова API.

### Механизм сессий
- **Middleware (`src/middleware.ts`)**: Перехватывает все запросы к `/admin` и `/api/admin`. Использует объект `NextRequest` для проверки HTTP-only куки `admin_session`.
- **Логика проверки**: Если кука отсутствует или её значение не совпадает с эталонным (`authenticated_yuransis`), Middleware выполняет `NextResponse.redirect` на страницу `/admin/login`. Для API-запросов возвращается JSON с кодом `401 Unauthorized`.
- **Маршрутизация**: Исключения настроены для путей `/admin/login` и `/api/admin/login`, чтобы предотвратить циклическую переадресацию.
- **Login API (`/api/admin/login`)**: Проверяет статические учетные данные. При успехе устанавливает куку с флагами:
  - `httpOnly: true` (защита от XSS, кука недоступна через JS).
  - `secure: true` (в режиме production, передача только через HTTPS).
  - `maxAge: 7 days` (длительность сессии).

## 2. Единая база лидов (Global Lead Unification)

Самая сложная часть системы — объединение разрозненных данных из Google Sheets в единый профиль клиента.

### Алгоритм агрегации (`uniqueLeads`)
Процесс происходит в `useMemo` для оптимизации производительности:
1. **Raw Data Ingestion**: Загружаются данные из всех вкладок (Вебинар, Практикум, Брони). Каждая строка получает мета-поле `_sheet` (название источника).
2. **Нормализация (Normalization)**:
   - **Телефон**: Регулярное выражение `/\D/g` удаляет пробелы, скобки и дефисы. `380 (68) 123-45-67` превращается в `380681234567`.
   - **Telegram**: Принудительный `toLowerCase()`, `trim()` и удаление лидирующего `@`. `@User_Name` превращается в `user_name`.
3. **Идентификация и Склеивание**:
   - Создается `Map<string, Lead>`. Ключом (`identifier`) служит первый доступный параметр в приоритете: **Phone > Telegram > VisitorID**.
   - Если ключ уже есть в `Map`, запись считается дубликатом. Вместо создания нового лида, в существующий объект в массив `_allSheets` добавляется название новой таблицы.
   - Если ключа нет, создается новая запись.
4. **Fallback ID**: Если у лида нет ни телефона, ни ТГ, ни ID (ручной ввод), генерируется временный `temp-ID` на основе `Math.random()`, чтобы лид не "потерялся" в общем списке и по нему можно было кликнуть.

## 3. Трекинг пути клиента (Customer Journey & Analytics)

Система восстанавливает историю действий пользователя до момента покупки.

### Механика трекинга
- **Client Side**: В корневом `layout.tsx` или через хук `useAnalytics` генерируется `visitorId`. Он сохраняется в `localStorage`.
- **Event Logging**: При каждом переходе `useEffect` на `pathname` отправляет запрос в `/api/analytics`.
- **Data Storage**: Все клики сохраняются в отдельную вкладку Google Sheets `Трафік`.

### Реконструкция Timeline в админке
При открытии карточки лида:
1. Из общего массива `traffic` фильтруются записи, где `visitorId` совпадает с ID выбранного лида.
2. Массив трафика объединяется с массивом всех регистраций (лидов) этого пользователя.
3. Результат сортируется по дате (`descending`).
4. В UI это отображается как "Событийная лента":
   - **Page View**: "Посмотрел страницу Цены" (серая иконка).
   - **Lead Created**: "Зарегистрировался на Вебинар" (яркая иконка с названием таблицы).

## 4. Интеграция с Google Sheets (GAS Webhooks)

Админка не просто читает данные, но и управляет ими через API Google Apps Script.

### Обработка статусов
- **Двусторонняя связь**: В админке реализована функция `updateLeadStatus`. Она делает POST запрос к GAS.
- **Поиск строки**: GAS скрипт принимает `orderId` и `targetSheet`. Он перебирает строки в указанной таблице, находит нужную и обновляет ячейку в колонке "Статус Оплати".
- **Global Sync**: Скрипт также обновляет статус в сводном листе `Аналітика Ліди`. Это гарантирует, что если менеджер изменит статус в основной таблице вручную, админка увидит это при следующем обновлении данных.

## 5. Расчет доходов (Revenue Intelligence)

Система умеет "читать" деньги, зашитые в текстовые поля тарифов.

### Логика калькулятора
1. **Фильтрация**: Берутся только лиды со статусом "Оплачено" (или содержащие "Оплат").
2. **Парсинг тарифа**:
   - Ищется подстрока "PRO" или "VIP" в полях `tariff`, `Тариф`, `Пакет`.
   - Если найдено "PRO" -> прибавляется **19$**.
   - Если найдено "VIP" -> прибавляется **39$**.
3. **Конвертация**: Все расчеты ведутся в USD для стабильности метрик, но отображаются с соответствующими символами.
4. **Динамика**: При переключении фильтра дат (например, "За сегодня"), `totalRevenue` пересчитывается мгновенно на лету только для отфильтрованного подмножества данных.

## 6. UI/UX Архитектура

Интерфейс построен на принципах **Reactive Dashboard**:
- **State Management**: Используются стандартные `useState` для фильтров, но вся тяжелая логика фильтрации и поиска вынесена в `useMemo`. Это позволяет интерфейсу не "фризить" при поиске по 1000+ записям.
- **Framer Motion**:
  - `AnimatePresence` управляет модальным окном. Это позволяет модалке плавно "выезжать" и "растворяться" при закрытии.
  - Ряды таблицы имеют `whileHover` эффекты для визуального отклика.
- **Copy-to-Clipboard**: Реализовано через `navigator.clipboard.writeText` с мгновенным изменением иконки на "Check", что улучшает UX для менеджеров продаж.

## 7. Система постоянных комментариев (Persistent Comment System)

Добавлена возможность внесения заметок менеджерами непосредственно через CRM-панель.

### Техническая реализация:
1.  **Frontend Logic**:
    *   В модальном окне лида добавлена секция "Нотатки менеджера" с `textarea`.
    *   Используется локальный стейт `localComment`, который инициализируется данными лида при открытии модалки.
    *   Кнопка "Зберегти" появляется только при изменении текста и вызывает функцию `saveComment`.
2.  **API Интеграция**:
    *   Запрос отправляется на `/api/admin/update` с `action: 'update_comment'`.
    *   Передаются `orderId` (идентификатор), `targetSheet` (исходная таблица) и сам текст комментария.
3.  **Backend (Google Apps Script)**:
    *   Функция `updateFieldInSheet` была генерализирована. Теперь она ищет колонку по имени (в данном случае "Коментар").
    *   **Авто-провизионинг**: Если в таблице (исходной или глобальной) отсутствует колонка "Коментар", GAS автоматически создает её в конце таблицы при первом же сохранении заметки.
    *   **Синхронизация**: Комментарий сохраняется одновременно и в исходной таблице проекта (например, "Лиды Вебинар"), и в общей таблице "Аналітика Ліди".
4.  **UI Индикация**:
    *   В общем списке лидов добавлена иконка "Активність" (Activity) рядом с номером заказа, если у лида есть заполненный комментарий. Это позволяет менеджеру сразу видеть, по каким клиентам уже велась работа.
